# ES Query Service

Веб-сервис для выполнения запросов к Elasticsearch:

- **запуск** — сразу, отложенно (в заданные дату и время) или по расписанию (cron);
- **результат** (JSON-ответ ES) можно:
  - отправить POST-запросом на указанный адрес (webhook) с произвольными заголовками;
  - скачать файлом;
  - хранить в сервисе заданное время (минуты, часы, дни) и поделиться публичной ссылкой.

Работает с несколькими кластерами. Есть локальные пользователи и роли: роль задаёт ключи доступа к кластерам,
а в истории запусков видно, кто запустил запрос.

Сервис работает с REST API Elasticsearch напрямую, поэтому подходит для ES 7.x/8.x/9.x и OpenSearch.

## Быстрый старт

### Docker Compose

```bash
cp .env.example .env          # при необходимости поправьте настройки
docker compose up -d --build
```

Интерфейс: http://localhost:8000

Контейнер запускается в сети хоста (`network_mode: host`): к Elasticsearch и адресам webhook он обращается так же, как
сама машина. Например, `http://localhost:9200` — это Elasticsearch на этом хосте. Сервис слушает порт 8000 хоста.

### Без Docker

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env          # TIMEZONE, ADMIN_USERNAME/ADMIN_PASSWORD ...
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### Первый запуск

1. **Администратор.** Пока пользователей нет, любая страница открывает форму **«Создание администратора»**.
   Можно создать его заранее: задайте `ADMIN_USERNAME` и `ADMIN_PASSWORD`, и он появится при старте.
   Пока администратора нет, сервис не защищён: создайте его сразу после запуска.
2. **Первый кластер.** Затем откроется форма **«Подключение к Elasticsearch»**: адрес, первый ключ доступа и
   «Не проверять TLS-сертификат».

## Пользователи, роли и доступ

Раздел **«Администрирование»** виден только администраторам. В нём три вкладки:

- **Пользователи** — логин, имя (показывается в истории), пароль, роли, флаг «Администратор», блокировка.
  При блокировке или смене пароля все сессии пользователя завершаются. Нельзя удалить или заблокировать себя,
  а также последнего активного администратора.
- **Роли** — набор ключей доступа. Пользователь с ролью видит только кластеры, к ключам которых даёт доступ
  хотя бы одна его роль, и выполняет запросы только с этими ключами. Пользователю можно выдать несколько ролей.
- **Кластеры и ключи** — у каждого кластера может быть несколько ключей. Ключ — это API-ключ ES или «без авторизации».
  Например, `reader-logs` с доступом к индексам логов и `reader-billing` с доступом к биллингу.

Как работает доступ:

- **Администратор** видит все кластеры, ключи и задачи.
- **Пользователь** видит задачи, которые используют доступные ему ключи, и может их запускать и редактировать:
  роль работает как команда. В форме запроса он выбирает кластер и ключ только из доступных.
- **Запуски по расписанию** выполняются от имени автора задачи. Если у автора отозвать доступ к ключу,
  заблокировать или удалить его, запуск завершится ошибкой с понятным текстом. Чтобы задача снова заработала,
  её должен пересохранить пользователь с доступом.
- **История запусков** показывает пользователя: кто нажал «Выполнить» или, для расписания, автора задачи.
  Имя сохраняется в истории, даже если пользователя потом удалят.

Каждый пользователь может сменить свой пароль в **личном кабинете** (клик по имени в шапке). Там же видны его роли и доступные ключи.

### Кластеры

Для кластера задаются название, адрес (`https://es.example.com:9200`) и «Не проверять TLS-сертификат»
(для самоподписанных сертификатов). Для ключа — название и API-ключ: значение *encoded* из Kibana
(Stack Management → API keys) или пара `id:api_key`.

Кнопка «Проверить подключение» показывает имя и версию кластера или понятную ошибку: неверный ключ,
проблема с сертификатом, кластер недоступен. «Сохранить» тоже сначала проверяет подключение. Если кластер
временно недоступен, появится кнопка «Сохранить без проверки». Изменения применяются сразу, перезапуск не нужен.
Ключ на странице не показывается: если оставить поле пустым, сохранённый ключ не изменится.

Кластер **по умолчанию** подставляется в форму нового запроса. На странице кластера видно, доступен ли каждый ключ.
Индикатор в шапке показывает, сколько кластеров доступно текущему пользователю.
Ключ или кластер, которые используются в задачах, удалить нельзя: сначала переключите задачи на другие ключи
или удалите их. Название кластера передаётся в webhook в заголовке `X-ES-Cluster` (URL-encoded).

## Запуск по внешнему вебхуку

Задачу можно запускать из внешней системы (мониторинг, CI, скрипт) POST-запросом на её секретный адрес.
Включается галочкой «Также запускать по внешнему вебхуку» в форме задачи или кнопкой «Включить» на странице задачи.
Работает вместе с любым режимом, в том числе с расписанием.

```bash
curl -X POST https://es-query.example.com/hooks/<token>                  # 202: run_id, status_url
curl -X POST "https://es-query.example.com/hooks/<token>?wait=1&timeout=60"  # ответ Elasticsearch
curl https://es-query.example.com/hooks/<token>/runs/<run_id>            # статус запуска
curl https://es-query.example.com/hooks/<token>/runs/<run_id>/result     # сохранённый результат
```

- **Ответ на запуск** — JSON: `run_id`, `status`, `status_url`, а когда результат сохранён — `result_url`.
  С `?wait=1` сервис дожидается выполнения и возвращает ответ Elasticsearch как есть (`X-ES-Run-Id` в заголовке),
  при ошибке Elasticsearch — код 502 с текстом ошибки. Если запрос не уложился в `timeout`, вернётся 202 со статусом `running`.
- **Результат** доставляется по настройкам задачи: хранение, публичная ссылка, отправка на адрес.
  Если хранение не включено, результат хранится `DEFAULT_RESULT_TTL_MINUTES` минут, чтобы его можно было забрать по `result_url`.
- **Права:** запуск идёт от имени автора задачи. Если у автора нет доступа к ключу задачи или он заблокирован,
  запуск завершится ошибкой.
- **Защита:** доступ только по секретному токену в адресе (256 бит). Можно ограничить IP-адреса и подсети
  вызывающих систем. Лимит вызовов в минуту пользователь задаёт в настройках вебхука задачи; он не может
  превышать `HOOK_RATE_LIMIT_PER_MINUTE` (по умолчанию 30). Пустое поле — действует этот максимум. Если максимум
  снизили после сохранения задачи, действует меньшее значение. Сверх лимита вызовы отклоняются с кодом 429.
  Принимается только POST, поэтому случайное открытие ссылки в браузере или предпросмотр в мессенджере задачу не запускают.
  Адрес можно перевыпустить (старый перестаёт работать) или отключить.
- **История:** запуски с триггером «вебхук» видны в истории вместе с IP вызывающего.

## Типы запросов и профилирование

Тип запроса определяется по эндпоинту: **Поиск** (`_search`, `_msearch`, шаблоны, `_async_search`, `_eql/search`),
**Подсчёт** (`_count`), **SQL / ES|QL** (`_sql`, `_query`), **Прочее** (`_cat`, `_mapping` и т.д.).
В списке задач есть вкладки по типам, у поисковых запросов — колонки «Скорость» и «Сложность».

**Профилирование** поисковых запросов выполняется через Profile API Elasticsearch (`"profile": true`):

- **Один раз для версии запроса.** Профиль привязан к отпечатку: кластер + метод + путь + тело в каноническом виде.
  Форматирование тела и порядок ключей на отпечаток не влияют. Профиль строится в фоне после сохранения задачи.
  Если тогда не получилось (например, кластер был недоступен), он строится после следующего успешного запуска.
  Обычные запуски профилирование не повторяют. Изменили запрос — изменился отпечаток — профиль строится заново.
  Задачи с одинаковым запросом на одном кластере используют общий профиль. Можно перепрофилировать вручную.
- **Скорость:** `took` профилированного запроса и уровень (быстрый < 100 мс, нормальный < 1 с, медленный < 10 с).
- **Сложность для кластера:** оценка 0–100 и уровень (низкая / средняя / высокая / очень высокая). Учитывается:
  суммарное время работы шардов по фазам (query, rewrite, агрегации, fetch), число шардов и перекос между ними,
  размер дерева запроса, дорогие конструкции (wildcard с `*` в начале, regexp, fuzzy, script, nested, join,
  большие terms), агрегации и их вложенность, большой `size` и глубокая пагинация, `track_total_hits`.
- **Факторы и рекомендации:** что именно нагружает кластер и как это исправить. Полный профиль можно скачать.
- **Скорость по реальным запускам:** каждый запуск поиска сохраняет `took` из ответа (читаются только первые байты
  ответа). На странице задачи показаны последний, средний, p95, минимальный и максимальный `took` и полное время.

Profile API поддерживается для `_search` и `_msearch`. Для остальных поисковых эндпоинтов скорость считается по запускам.
Профилирование — это дополнительное выполнение запроса с накладными расходами Profile API, но только один раз на версию запроса.

## Как пользоваться

1. **Новый запрос** — укажите метод, путь (`/logs-*/_search`, `/idx/_count`, `/_sql?format=json`, `/_msearch`) и тело в JSON.
2. **Когда выполнить:**
   - *Сейчас* — кнопки «Выполнить» (откроется страница с результатом) или «Выполнить и скачать» (файл скачается сразу);
   - *Отложенно* — дата и время в часовом поясе `TIMEZONE`; после запуска задача помечается выполненной;
   - *По расписанию* — cron из 5 полей (`*/15 * * * *`, `0 9 * * mon-fri`).
3. **Куда отправить результат** (можно выбрать несколько вариантов):
   - *Отправить на адрес* — POST с телом ответа ES и заголовками `Content-Type`, `X-ES-Task-Id`, `X-ES-Run-Id`,
     `X-ES-Task-Name`, `X-ES-Cluster`, а также вашими (например, `Authorization: Bearer ...`). Отправляется только успешный ответ;
     если адрес не ответил, будет ещё до `WEBHOOK_RETRIES` попыток;
   - *Сохранить в сервисе* — на заданный срок, с публичной ссылкой или без неё.
     На странице запуска срок можно продлить, ссылку создать или отозвать, а результат удалить.

Результат ручного запуска можно посмотреть и скачать, даже если хранение не включено: он хранится
`DEFAULT_RESULT_TTL_MINUTES` минут.

Публичная ссылка `/s/<token>` открывается без авторизации и показывает JSON. С параметром `?download=1` ответ скачивается файлом.
Ссылка перестаёт работать, когда истекает срок хранения или её отзывают.

## Настройки

Задаются переменными окружения или в файле `.env`. Полный список с описаниями — в [.env.example](.env.example).

| Переменная | По умолчанию | Описание |
|---|---|---|
| `ES_URL`, `ES_API_KEY`, `ES_VERIFY_CERTS` | `http://localhost:9200`, —, `true` | Только начальные значения для первого кластера |
| `ES_CA_CERTS` | — | CA-сертификат кластера (используется, когда проверка TLS включена) |
| `ES_USERNAME` / `ES_PASSWORD` | — | Basic-авторизация в ES, если API-ключ не задан |
| `ES_READ_ONLY` | `true` | Разрешены только читающие запросы (GET и POST на `_search`, `_count`, `_msearch`, `_sql`, `_esql`, `_mget`, …) |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | — | Первый администратор, создаётся при старте, если пользователей ещё нет |
| `SESSION_TTL_HOURS` | `12` | Сколько действует вход |
| `TIMEZONE` | `UTC` | Часовой пояс для расписаний и отображения времени |
| `PUBLIC_BASE_URL` | — | Внешний адрес для публичных ссылок, если сервис стоит за прокси |
| `MAX_RESULT_MB` | `200` | Максимальный размер ответа ES |
| `MAX_RESULT_TTL_DAYS` | `90` | Максимальный срок хранения |
| `RUN_HISTORY_DAYS` | `30` | Сколько хранить историю запусков |
| `DATABASE_URL` | SQLite в `DATA_DIR` | Можно указать PostgreSQL (нужен драйвер, например `psycopg`) |

## Устройство

```
app/
  main.py           приложение, проверка входа, задачи и запуски (FastAPI + Jinja2)
  auth_routes.py    вход, выход, создание первого администратора, личный кабинет
  admin_routes.py   администрирование: пользователи, роли, кластеры, ключи
  access.py         права доступа: какие ключи доступны пользователю
  security.py       пароли (scrypt), сессии, защита от перебора
  web.py            шаблоны и общие функции веб-страниц
  profiler.py       типы запросов, профилирование поиска, оценка скорости и сложности
  hooks.py          входящие вебхуки: запуск задачи внешней системой
  executor.py       выполнение: запрос в ES → сохранение → webhook
  scheduler.py      APScheduler: отложенные и cron-задачи, очистка просроченных результатов
  es.py             HTTP-клиенты по ключам доступа (меняются на лету), проверка пути, тела и режима только-чтение
  clusters.py       кластеры и ключи из БД, доступные пользователю ключи
  db.py             подключение к БД и миграции со старых версий
  storage.py        файлы результатов на диске (DATA_DIR/results) и очистка
  models.py         задачи, запуски, кластеры, ключи, пользователи, роли (SQLAlchemy)
```

- Задачи и история хранятся в БД. При старте сервис заново ставит в планировщик все активные задачи.
  Отложенные задачи, время которых наступило, пока сервис был выключен, выполняются сразу после старта.
- Результаты хранятся файлами в `DATA_DIR/results`. Просроченные удаляются раз в `CLEANUP_INTERVAL_MINUTES` минут.

## Безопасность

- Вход по логину и паролю. Пароли хранятся только как хеш scrypt. Сессия — случайный токен в cookie
  с флагами `HttpOnly` и `SameSite=Lax` (`Secure` при работе по HTTPS); в БД хранится только хеш токена.
  После 5 неудачных попыток входа логин блокируется на 15 минут.
- Не оставляйте сервис без администратора: пока его нет, первый открывший страницу может им стать.
- Права проверяются на сервере: задачу, запуск или результат с недоступным ключом пользователь не увидит даже по прямой ссылке.
- API-ключи хранятся в БД сервиса (`DATA_DIR/service.db`) в открытом виде. Ограничьте доступ к каталогу данных.
  Создавайте в ES ключи с минимально нужными правами (`read`, `view_index_metadata` на нужные индексы):
  роль в сервисе ограничивает выбор ключа, а ключ ограничивает, что можно прочитать в ES.
- Не отключайте `ES_READ_ONLY` без необходимости. Ещё лучше — дать сервису в ES пользователя с правами только на чтение.
- Публичные ссылки содержат случайный токен из 192 бит. Доступ к результату есть у любого, у кого есть ссылка.
- POST-запросы со сторонних сайтов отклоняются по заголовкам Origin/Referer (защита от CSRF).
